HARDENING TLS - EXPANSAO DO CERTIFICADO LET'S ENCRYPT PARA O SUBDOMINIO "www"
==============================================================================

Contexto
--------
O deploy (deploy-ubuntu.sh) emite o certificado inicial apenas para o domínio
principal:

    DOMAIN_NAME="deppi.maracanau.ifce.edu.br"
    sudo certbot --nginx -d $DOMAIN_NAME

Isso significa que "https://www.deppi.maracanau.ifce.edu.br" NAO esta coberto
pelo certificado atual. Para adicionar o subdominio "www" ao certificado
existente (expandindo-o, em vez de emitir um certificado novo e separado),
rode o comando abaixo no servidor onde o Nginx e o Certbot estao instalados.

Comando exato
--------------
sudo certbot --nginx -d deppi.maracanau.ifce.edu.br -d www.deppi.maracanau.ifce.edu.br --expand

Observacoes
-----------
1. A flag --expand e obrigatoria: sem ela, o Certbot pede confirmacao
   interativa antes de expandir um certificado ja existente para incluir
   novos dominios, o que trava execucoes automatizadas/no-terminal.
2. O Certbot detecta automaticamente o certificado atual pelo nome do site
   configurado em /etc/nginx/sites-available/deppi e atualiza tanto o
   certificado quanto o bloco "server" do Nginx (listener 443 + redirect
   HTTP->HTTPS), sem necessidade de editar o nginx.conf manualmente.
3. Certifique-se de que o DNS do subdominio "www" ja aponta para o mesmo
   servidor antes de rodar o comando, senao a validacao HTTP-01 do
   Let's Encrypt falha.
4. Se o dominio real do ambiente de producao for diferente do usado acima,
   substitua "deppi.maracanau.ifce.edu.br" pelo valor de DOMAIN_NAME
   configurado em deploy-ubuntu.sh antes de executar o comando.
5. Apos a expansao, valide com:
       sudo certbot certificates
       sudo nginx -t && sudo systemctl reload nginx
